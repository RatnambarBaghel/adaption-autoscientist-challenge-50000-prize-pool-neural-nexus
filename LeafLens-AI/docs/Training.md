# 🧪 LeafLens AI — Model Training

## 1. Training Overview

LeafLens AI uses **Adaption AutoScientist** to fine-tune a vision-language model for crop disease identification from leaf images.

The training workflow used the adapted dataset generated by Adaption's **Adaptive Data** platform.

```text
9,488-row Adapted Dataset
          │
          ▼
     AutoScientist
          │
          ▼
Gemma Vision-Language Model
          │
          ▼
      LoRA Fine-tuning
          │
          ▼
   Trained Crop-Disease Model
          │
          ▼
 Evaluation Against Baseline

 ```

 The objective of training was to improve the model's performance on the crop-disease identification task compared with the provided baseline model.

Training Platform:

- Platform: Adaption AutoScientist
- Training method: LoRA fine-tuning
- Dataset: Adaption Adaptive Data output
- Adapted dataset size: 9,488 rows
- Task: Crop disease identification from leaf images
- Model family: Gemma Vision-Language Model

---

## 2. Final Training Configuration

The final model was fine-tuned using **Supervised Fine-Tuning (SFT)** with **Low-Rank Adaptation (LoRA)** through Adaption AutoScientist.

The training configuration used for the documented experiment was:

| Parameter | Configuration |
|---|---|
| Base model | `google/gemma-3-27b-it-VLM` |
| Base model size | 27B |
| Training method | SFT |
| Fine-tuning type | LoRA |
| Data format | Chat |
| Epochs | 16 |
| Batch size | Maximum supported |
| Learning rate | 0.0001 |
| Learning-rate scheduler | Cosine |
| Scheduler cycles | 0.5 |
| Warmup ratio | 0.1 |
| Minimum learning-rate ratio | 0.1 |
| LoRA rank (`r`) | 64 |
| LoRA alpha | 128 |
| LoRA dropout | 0 |
| Weight decay | 0 |
| Maximum gradient norm | 2 |
| Train on inputs | False |
| Evaluation runs | 5 |
| Trainable LoRA modules | `q_proj`, `k_proj`, `v_proj`, `o_proj` |

### 2.1 LoRA Configuration

LoRA was used to adapt the 27B vision-language model without updating all of the base model parameters directly.

The final configuration used:

```text
LoRA rank (r):       64
LoRA alpha:         128
LoRA dropout:         0

```

The LoRA adapters were applied to the following attention projection modules:

- q_proj
- k_proj
- v_proj
- o_proj

### 2.2 Optimization Configuration

The training run used:

Learning rate:          0.0001
Scheduler:              cosine
Warmup ratio:           0.1
Weight decay:           0
Maximum gradient norm:  2
Scheduler cycles:       0.5

The cosine learning-rate schedule was used to gradually adjust the learning rate during training.

### 2.3 Training Objective

The model was trained using supervised fine-tuning on the adapted agricultural dataset.

The training objective was to improve the model's ability to associate leaf images with the corresponding crop-disease diagnosis.

The training was performed for 16 epochs, with evaluation performed during the training process.

### 2.4 Reproducibility

The exact training configuration is preserved in the project's training configuration file so that the experiment can be documented and reproduced as closely as possible.

## 3. Training Process

The final training experiment was executed through **Adaption AutoScientist** using the 9,488-row dataset generated by Adaptive Data.

### 3.1 Training Workflow

The training process followed these stages:

```text
9,488-row Adaptive Data Dataset
              │
              ▼
        AutoScientist Setup
              │
              ▼
      Base VLM Initialization
              │
              ▼
        LoRA Configuration
              │
              ▼
    Supervised Fine-Tuning
              │
              ▼
      Periodic Evaluation
              │
              ▼
      Final Model Checkpoint

```

### 3.2 Base Model

The experiment started from:

    google/gemma-3-27b-it-VLM

The base model is a 27-billion-parameter vision-language model capable of processing multimodal inputs.

The model was adapted specifically for the agricultural crop-disease identification task.

### 3.3 Fine-Tuning Method

The training used:

    Supervised Fine-Tuning (SFT)
    Low-Rank Adaptation (LoRA)

LoRA was selected to efficiently adapt the large base model while avoiding full parameter fine-tuning.

The adapters were applied to:

- q_proj
- k_proj
- v_proj
- o_proj

### 3.4 Training Data

The training input was the 9,488-row dataset produced by Adaptive Data.

The data was provided in chat format and used for supervised fine-tuning.

The training configuration disabled training directly on the input portion of the examples:

    train_on_inputs = false

### 3.5 Training Schedule

The final experiment ran for:

    16 epochs

The learning rate was:

    0.0001

with a cosine learning-rate schedule and:

    Warmup ratio = 0.1
    Scheduler cycles = 0.5

### 3.6 Evaluation During Training

The experiment configuration specified:

    Number of evaluations = 5

These evaluations were used during the training process to monitor model performance and help assess the training run.

Detailed training metrics and the final comparison with the baseline are documented in Evaluation.md.

## 4. Training Results

The final training experiment was monitored through Adaption AutoScientist's training and evaluation dashboards.

### 4.1 Training Metrics

The AutoScientist dashboard provided monitoring of several training signals, including:

- Training loss
- Validation loss
- Learning rate
- Gradient norm
- Global training step

These metrics were used to monitor the optimization process throughout training.

### 4.2 Training Loss

Training loss was monitored throughout the training run to observe how the model optimized against the training data.

The training dashboard provides the loss curve across training steps and can be used to assess the optimization behavior of the final run.

### 4.3 Validation Loss

Validation loss was monitored separately from training loss to provide an indication of model behavior on held-out evaluation data during training.

The validation curve is included in the project's training results and should be interpreted together with the final evaluation metrics rather than as a standalone measure of disease-classification accuracy.

### 4.4 Learning Rate

The training dashboard recorded the learning-rate schedule throughout the experiment.

The final configuration used a cosine learning-rate schedule with:

- Initial learning rate: `0.0001`
- Warmup ratio: `0.1`
- Scheduler cycles: `0.5`

### 4.5 Gradient Norm

Gradient norm was also monitored during training.

The final configuration used a maximum gradient norm of:

```text
2

```

This helped control unusually large gradient updates during optimization.

### 4.6 Baseline Comparison

The final model was evaluated against the baseline using Adaption's evaluation system.

The evaluation showed a measurable performance improvement over the baseline.

The exact baseline and adapted win-rate results will be documented in the final evaluation section using the values reported by the Adaption evaluation dashboard.

### 4.7 Interpretation

Training metrics such as loss, learning rate, and gradient norm describe the optimization process.

They should not be interpreted as direct crop-disease classification accuracy.

The primary performance comparison for the hackathon is the model's measured improvement over the provided baseline on Adaption's held-out evaluation system.
